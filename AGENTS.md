# Instructions for AI assistants working in the L2M Ops repository

This repository is the **L2M Ops platform**: a Streamlit website for the game operations team, made of the platform's own
features and team members' **plugins** (`plugins/<id>/`). Users may not be programmers — explain briefly and simply, in the
language the user writes in.

## When helping a member build or change a plugin

1. **Read `PLUGIN_GUIDE.md` before writing code** and follow every section. These are the team's shared rules.
2. **Only create / change files inside that plugin's `plugins/<id>/`.** Do not change `core/`, `ui/`, `views/`,
   `automation/`, `tools/`, `app.py`, `requirements.txt` or anyone else's plugin — even when it looks easier.
3. New plugin: copy `plugins/_template` to `plugins/<id>` and set `id` in `plugin.toml` to the folder name.
4. Use the platform **only through** `from core import sdk` (see each function's docstring in `core/sdk.py`).
5. Save data with `sdk.save` / `sdk.load`, using the **shared ID fields** (PLUGIN_GUIDE.md section 5.2) and stable record keys.
6. Widget / `st.session_state` keys use `sdk.key("…")`; displayed text is wrapped in `sdk.t("…")` with `locales.py` holding
   the other language; check `sdk.can_edit()` before saving / editing / deleting; use `sdk.now()` for the current time.
7. Never write keys / passwords / tokens into files — use `sdk.secret("NAME")` and remind the user to send the value to the admin.
8. After every change:
   - run `.venv\Scripts\python.exe tools\check_plugins.py plugins\<id>` (non-Windows: `python tools/check_plugins.py plugins/<id>`)
     and fix until it reports `OK`;
   - remind the user to try it with `run.bat`;
   - update the plugin's `README.md` (saved data, changes) and bump `version` in `plugin.toml`.
9. Needs the platform does not cover yet (new library, secret, scheduled runs, VPN / browser, heavy work): **do not change
   the core**. Write it in the README section "Needs from the platform" and tell the user to contact the admin.
10. Turning an existing app into a plugin: keep its business logic, replace its storage with sdk, add an import button for
    the old app's data.
11. Users working with a chat AI (ChatGPT, Gemini, Copilot…) use `AI_PROMPT.md` (downloadable from the Team plugins page,
    generated by `core/bundle.py: ai_prompt()`) — the same rules plus an answer format the platform splits into files.

## When the user is the platform admin and asks to change the core

Change it as asked. Keep `core/sdk.py` backward compatible (plugins depend on it): adding functions is fine; renaming /
removing functions or changing the meaning of parameters is not. When the rules change, update `PLUGIN_GUIDE.md`,
`core/plugins.py` (the checks) and `ROADMAP.md` together.
